# 카드옵티마 (Card Optima) — 최적 결제 카드 추천 MVP

여러 장의 신용카드를 보유한 사용자가 **"지금 어디에서 얼마를 결제할 것인지"** 입력하면,
전월 실적·월 할인 한도·포인트/마일 환산 가치·이벤트 조건을 계산해 **가장 유리한 카드를 즉시 추천**하는
모바일 퍼스트 PWA입니다. 서버 없이 브라우저 `localStorage`에 저장되므로 바로 실행할 수 있습니다.

- 프런트엔드: React 18 + TypeScript + Vite 5 + Tailwind CSS 3
- 상태 저장: `localStorage` (JSON 내보내기/불러오기, 결제내역 CSV 가져오기)
- 테스트: Vitest (계산 엔진·카탈로그 단위 테스트 37개)
- PWA: `manifest.webmanifest`, 아이콘 3종, 서비스 워커(오프라인 캐시)

## 1. 실행 방법 (로컬)

Node.js 18 이상이 필요합니다.

```bash
cd projects/card-optimizer
npm install
npm run dev        # http://localhost:5173 (--host 로 실행되어 같은 Wi-Fi의 폰에서도 접속 가능)
```

스마트폰에서 보려면 PC와 같은 네트워크에서 `http://<PC IP>:5173` 으로 접속한 뒤
브라우저 메뉴의 **"홈 화면에 추가"** 로 설치하면 앱처럼 열립니다(PWA).

### 빌드 · 미리보기

```bash
npm run build      # tsc --noEmit + vite build → dist/
npm run preview    # 빌드 결과를 로컬 서버로 확인
```

### 테스트

```bash
npm test           # vitest run (37개)
```

테스트 범위: 신세계백화점 30만 원 / 대한항공 공홈 150만 원 / 월 한도 초과 / 전월 실적 미달 /
결제 취소 반영 / 실적 제외 업종·건당 최소금액 / 분할 결제 시뮬레이션 / CSV·JSON 입출력 / AI 비서 답변 /
카탈로그 검색·자동 입력·바우처 연동 / 구버전 저장 데이터 업그레이드.

## 2. 화면 구성 (하단 5탭)

| 탭 | 내용 |
|---|---|
| **홈** | 이번 달 받은 혜택 합계, 당월 인정 실적, 전월 충족 카드 수, 카드별 실적 진행률, 실적 부족 카드, 45일 내 소멸 혜택(D-day), 최근 결제 |
| **결제 추천** | 금액·업종·가맹점 입력 → 5장 전체 비교. 빠른 프리셋(신세계백화점 30만 / 대한항공 150만 / 해외 80만 / 롯데면세점 50만). 1~3위 + 전체 순위, 즉시 혜택·실적 영향·이유·주의사항 상세 |
| **내 카드** | **카드 검색으로 자동 입력**(카탈로그 14종 — 카드명·카드사·키워드 검색, 빠른 선택 칩) 후 숫자만 확인해 저장, 카드 추가·수정·삭제, 혜택 규칙(업종·정률/포인트·월 한도·전월 조건) 편집, 실적 수동 보정, 결제내역 추가/취소 |
| **혜택 지갑** | 숙박권·라운지·발레파킹·바우처·크레딧 잔여 횟수 +/-, 만료일 D-day, 이용 조건·예약 방법 |
| **AI 비서** | 로컬 규칙·계산 엔진 기반 자연어 Q&A (실적 우선순위, 소멸 혜택, 해외 결제, 분할 결제, 연회비 효율 등) |

### 결제 추천 결과의 원칙

- **즉시 혜택**(할인·적립의 원화 환산액, 월 한도 반영)과 **향후 실적 기여 가치**(추정)를 **분리 표시**합니다.
  두 값은 합산하지 않으며, 순위는 즉시 혜택 기준입니다.
- 향후 가치는 점선 박스에 "확정 아님"으로 표시하고, 산정 기준(부족액 대비 기여 비율 × 실적 조건 혜택의 월 기대값)을 함께 보여줍니다.
- 이벤트(응모형) 혜택은 조건 충족 여부와 진행률을 별도 표시하며 즉시 혜택에 더하지 않습니다.
- 계산 결과에는 근거(전월 실적, 잔여 한도, 직판 조건, 예시 데이터 여부)와 주의사항이 함께 나옵니다.

## 4. 카드 카탈로그 & 초기 샘플 카드

찾으면 연회비·브랜드·전월 실적 기준·실적 제외 업종·혜택 전체·대표 바우처가 **한 번에 자동 입력**됩니다.
숫자만 확인하고 `저장`하면 끝이고, 목록에 없는 카드는 `직접 입력하기`로 기존처럼 넣을 수 있습니다.

## 5. 데이터 모델 요약

- `Card`: 별칭·카드명·카드사·브랜드·테마·끝 4자리(선택)·연회비·실적 기준(전월 기준/건당 최소/제외 업종·키워드)
  · 혜택 규칙 배열 · 이벤트 배열 · 수동 보정 · 이번 달 혜택 사용액 · 신뢰도(공식/예시)
- `BenefitRule`: 업종 배열, 가맹점 키워드, 방식(정률 % / 포인트 per 원), 월 한도(원 또는 포인트),
  전월 실적 조건, 건당 최소금액, 직판 조건, 신뢰도, 출처·메모
- `Transaction`: 카드, 가맹점, 업종, 금액, 날짜, 상태(정상/취소)
- `WalletItem`: 카드, 이름, 분류, 잔여/전체/단위, 만료일, 조건, 이용 방법, 추정 가치, 신뢰도
- `Settings`: 포인트 통화별 원화 가치(기본값: Bonvoy 10원, Hilton 7원, 스카이패스 15원, MR 1원)

계산 규칙

1. **실적 인정** = 해당 월·정상 상태·업종 제외 아님·건당 최소금액 이상·가맹점 키워드 제외 아님.
2. **전월 실적** = 전월 인정 실적 + 사용자 수동 보정.
3. **혜택** = 업종·키워드·최소금액·전월 조건을 통과한 규칙 중 **가장 유리한 1개**(중복 적립 미반영).
   월 한도(사용액 차감)로 상한을 적용합니다.
4. **다음 달 실적 기여** = 이번 결제가 당월 인정 실적으로 쌓여 다음 달 기준에 미치는 영향(별도 표시).
5. **분할 결제** = 1만 원 단위로 한계 혜택이 가장 큰 카드에 배분하는 그리디 시뮬레이션.

## 6. 데이터 백업 · 복원

- 홈/내 카드 상단 **⚙ 설정**에서:
  - **JSON 내보내기** — 카드·결제내역·지갑·설정 전체 백업
  - **JSON 불러오기** — 백업 복원(빠진 필드는 기본값으로 보정)
  - **결제내역 CSV** 내보내기 / **CSV 양식 받기** / **CSV 가져오기**
  - 포인트·마일 환산 가치 수정, 전체 초기화
- 저장 키: `localStorage["card-optimizer:v1"]`

### CSV 형식

```csv
날짜,카드,가맹점,업종,금액,상태,메모
2026-11-24,메리어트 본보이,신세계백화점,백화점,300000,정상,
2026-11-20,삼성 아멕스 플래티늄,롯데면세점,면세점,500000,취소,
```

- 날짜: `YYYY-MM-DD` 또는 `M/D`(올해로 해석)
- 카드: 카드명·별칭·끝 4자리로 매칭
- 업종: 한글 라벨(백화점·항공 공홈·해외결제·면세점·음식점·카페·온라인쇼핑·골프·호텔·숙박·대중교통·세금·공과금·일반) 또는 생략 시 가맹점명으로 추정
- 상태: `정상` / `취소`
- 영어 헤더(`date,card,merchant,category,amount,status,memo`)도 지원

## 7. 개인정보 · 보안

- **전체 카드번호, CVC, 비밀번호, 카드사 인증정보는 수집·저장하지 않습니다.** 타입 정의에도 해당 필드가 없습니다.
- 카드 식별은 별칭과 (선택) 끝 4자리까지만 사용합니다.
- 데이터는 이 브라우저의 `localStorage`에만 있고 외부로 전송되지 않습니다(외부 LLM·분석 도구 미연동).
- 다른 기기와 공유하려면 JSON 내보내기 파일을 직접 옮겨 불러오세요.

## 8. 배포 방법

> **현재 배포 주소: https://smartcheckinkr.github.io/card-optimizer/** (GitHub Pages, `gh-pages` 브랜치)
> 수정 후 다시 배포하려면 `npm run build` 결과를 `gh-pages` 브랜치로 올리면 됩니다.

빌드 결과(`dist/`)는 정적 파일이므로 어디서나 호스팅할 수 있습니다.

- **Vercel / Netlify**: 프로젝트 루트를 `projects/card-optimizer`로 지정, Build `npm run build`, Output `dist`
- **GitHub Pages**: `vite.config.ts`의 `base`를 `'./'`로 두었으므로 저장소 하위 경로 배포도 동작합니다.
  `dist/`를 `gh-pages` 브랜치로 올리면 됩니다.
- **사내/개인 서버**: `dist/`를 정적 서버(python -m http.server, nginx 등)로 서빙

> 소스는 `main` 브랜치, 배포 산출물(`dist/`)은 `gh-pages` 브랜치에 있습니다.
> GitHub Pages는 `gh-pages` 브랜치 루트를 배포 소스로 사용합니다(`.nojekyll` 포함).

## 9. 2단계 확장 지점

- `src/services/storage.ts`의 `StateRepository` 인터페이스를 구현한 `SupabaseRepository` 교체
  (스키마: `supabase/schema.sql`, 행 수준 보안 RLS 포함)
- 카드 승인 알림 자동 수집(안드로이드 앱), 마이데이터 연동은 별도 제휴·규제 검토 후
- 혜택 데이터 자동 갱신·변경 이력 비교, 만료 알림(푸시/스케줄)
- AI 비서의 외부 LLM 연동(질문 해석만 담당, 금액 계산은 현재 엔진 유지)

## 10. 알려진 한계 (MVP)

- 카드별 혜택은 **대표 1개 규칙**만 적용합니다(중복 적립·세부 제외 조건은 미구현).
- 이벤트 진행률은 이번 달 결제내역 기준 추정입니다.
- 연간 이용 실적 조건, 혜택 변경 이력 비교 화면은 2단계로 남겨 두었습니다(카드별 변경 이력 데이터 필드는 준비됨).
- 실적·한도는 사용자가 입력·보정한 값이며 카드사 공식 집계와 다를 수 있습니다.
- 외부 LLM은 연결되어 있지 않습니다. AI 비서는 규칙 기반이며, 해석하지 못한 질문은 그렇다고 답합니다.
